## Exact-PID sticky-unfreeze

The Baseline Profile startup generator was started through
`scripts/infinix-codex-retry.sh sticky-profile startup`. The runner found
controller PID `3846` and applied `am unfreeze --sticky 3846` while the process
was alive. During the still-active run, the controller was still PID `3846` and
its unified cgroup was `/apps/uid_10007/pid_3846`; its `cgroup.events` reported
`populated 1` and `frozen 1`.

Therefore the process-scoped workaround did **not** solve controller survival.
The run was interrupted after this evidence was captured; it is profile-capture
survivability evidence, not a timing result.

## Guarded device-wide fallback and rollback

Because the same live PID froze, the guarded helper was used:

```sh
bash scripts/infinix-freezer-session.sh disable --yes
```

It saved the original `null` state in
`device-test-results/freezer-session-20260920-110839/use_freezer.before.txt`,
requested `use_freezer=false`, and rebooted. After reconnect, both the helper's
post-reboot value and the live value were `null`, rather than the required
`false`. This XOS build did not retain the documented DeviceConfig override.
No benchmark or profile run was treated as freezer-disabled evidence.

The exact rollback helper was then run. The saved original value, the
post-rollback value, and the final live value all matched `null`; rollback is
verified.

The retry exposed a harness safety defect: the helper previously announced a
prepared diagnostic session without confirming the post-reboot value was
`false`. Commit `569e80b` makes it fail closed with recorded evidence instead.

## Decision and follow-up

Do not commit `baseline-prof.txt` or `startup-prof.txt` to production. The
required generation, `BaselineProfileMode.Require` packaging proof, repeated
equal-policy A/B data, frame-regression checks, and profile APK-size measurement
are all absent.

The launcher smoke validation and earlier partial-device findings remain in
`docs/device-tests/2026-09-20-infinix-7cae4bd.md`. This follow-up narrows the
remaining blocker: XOS freezes the exact sticky-unfrozen controller PID, and
also does not retain the documented device-wide `use_freezer=false` override
across reboot. A vendor-supported controller/freezer exemption, or a supported
way to make the documented override persist, is required before the requested
physical A/B can be completed.
